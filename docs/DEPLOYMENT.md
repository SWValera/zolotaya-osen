# Публикация: GitHub → Cloudflare Workers Static Assets

Сайт опубликован на Cloudflare Workers Static Assets: **https://zolotayaosen.kz/**; технический адрес **https://zolotaya-osen.arshavin-ivan-mail-ru.workers.dev/** остаётся доступен. Исходники хранятся в [SWValera/zolotaya-osen](https://github.com/SWValera/zolotaya-osen), production branch — `main`. R2, D1, KV, серверная логика и платные API не используются.

## 1. GitHub-репозиторий

Проект размещён в отдельном репозитории. Ветка `main` содержит готовый сайт и настройки публикации; исходная рабочая ветка `feat/static-resort-site` также сохранена. Чтобы получить проект на другом компьютере:

```sh
git clone https://github.com/SWValera/zolotaya-osen.git
cd zolotaya-osen
```

Для настройки Cloudflare используйте репозиторий `SWValera/zolotaya-osen` и ветку `main`. Не копируйте `.env`, токены или локальные кэши в Git.

## 2. Бесплатное статическое размещение

Проект `zolotaya-osen` уже опубликован. Ниже приведены настройки для его сопровождения или повторной настройки интеграции GitHub (Workers Builds):

- Каталог проекта: корень репозитория.
- Каталог статических файлов уже задан в `wrangler.jsonc`: `./public`.
- Build command: пустое поле (сборка не нужна); если интерфейс требует команду, используйте `npm run check`.
- Deploy command: `npx wrangler deploy`.
- Production branch: `main`.
- Никакие bindings и секреты приложения не нужны.

После подключения GitHub коммиты в выбранную ветку будут автоматически публиковаться. У проекта только Static Assets: платные хранилища и серверные вызовы не нужны. Проверьте актуальные лимиты бесплатного плана в своём аккаунте; платные опции не включайте.

Основной домен подключён владельцем через Cloudflare и открывает сайт по HTTPS. DNS управляется nameserver'ами Cloudflare; запись и сертификат уже созданы для Worker. Для запуска свежей версии отправьте обновлённые исходники в `main`, дождитесь production build и проверьте оба адреса.

## 3. Проверка конфигурации без публикации

При наличии Node.js:

```sh
npx wrangler deploy --dry-run
```

Это локальная проверка конфигурации, без развёртывания. Wrangler — инструмент публикации, не зависимость сайта. Для ручной публикации вместо GitHub-интеграции потребуется авторизованный Cloudflare CLI и команда `npx wrangler deploy`; в этой сессии она без `--dry-run` не выполнялась.

## 4. SEO основного домена

Для текущего адреса уже выполнена команда:

```sh
npm run seo -- https://zolotayaosen.kz
```

Она создаёт `public/robots.txt` и `public/sitemap.xml`, а также добавляет canonical и `og:url` в главную. После публикации проверьте их доступность именно на `zolotayaosen.kz`; sitemap должен вернуть XML с главным адресом. Затем отправьте sitemap в Google Search Console и Яндекс Вебмастер, если у владельца настроены эти инструменты.

Не публикуйте неподтверждённые фото, цены, валюту, вместимость, удобства, адрес и доступность. Онлайн-бронирования, календаря и оплаты нет. Перед поездкой посетитель связывается с администрацией по телефону.

## Обновления и кэш

Меняйте информацию об объекте в `public/assets/js/objects.js`; затем commit/push в подключённый репозиторий. JS/CSS требуют перепроверки кэша (`no-cache`), фото кэшируются сутки. При замене фотографии используйте новое имя файла, чтобы посетители сразу получили новую версию. Откат — возврат коммита или предыдущей версии в панели Cloudflare.
