# Публикация: GitHub → Cloudflare Workers Static Assets

Сайт подготовлен к размещению. В этой сессии сайт не публиковался, домен не подключался, ресурсы Cloudflare и удалённый репозиторий не создавались. R2, D1, KV, серверный Worker и платные API не используются.

## 1. Новый GitHub-репозиторий

Проект находится в отдельном локальном репозитории с рабочей веткой `feat/static-resort-site` и коммитом. Чужие репозитории не затрагивались. Создайте для этого проекта пустой репозиторий на GitHub, затем в корне проекта:

```sh
git remote add origin https://github.com/YOUR-ACCOUNT/zolotaya-osen.git
git push -u origin feat/static-resort-site
```

Замените адрес своим новым репозиторием. После просмотра результата перенесите ветку в `main` через PR или настройте публикацию с выбранной ветки. Не копируйте `.env`, токены или локальные кэши в Git.

## 2. Бесплатное статическое размещение

В Cloudflare Workers & Pages создайте проект Workers с интеграцией GitHub (Workers Builds). Выберите новый репозиторий:

- Каталог проекта: корень репозитория.
- Каталог статических файлов уже задан в `wrangler.jsonc`: `./public`.
- Build command: пустое поле (сборка не нужна); если интерфейс требует команду, используйте `npm run check`.
- Deploy command: `npx wrangler deploy`.
- Production branch: согласованная ветка, обычно `main`.
- Никакие bindings и секреты приложения не нужны.

После подключения GitHub коммиты в выбранную ветку будут автоматически публиковаться. У проекта только Static Assets: платные хранилища и серверные вызовы не нужны. Проверьте актуальные лимиты бесплатного плана в своём аккаунте; платные опции не включайте.

Сначала проверьте сайт на техническом адресе `workers.dev`. Основной домен подключайте только после разрешения владельца и проверки реальных данных.

## 3. Проверка конфигурации без публикации

При наличии Node.js:

```sh
npx wrangler deploy --dry-run
```

Это локальная проверка конфигурации, без развёртывания. Wrangler — инструмент публикации, не зависимость сайта. Для ручной публикации вместо GitHub-интеграции потребуется авторизованный Cloudflare CLI и команда `npx wrangler deploy`; в этой сессии она без `--dry-run` не выполнялась.

## 4. Перед основным доменом

1. Подтвердите номер телефона, реальные статусы объектов, цены, валюту, вместимость и удобства.
2. Замените демонстрационное фото и эскизы настоящими фотографиями, затем измените соответствующие подписи. Не удаляйте подпись «демонстрационное» до замены изображения.
3. Подтвердите местоположение базы; адрес в текущей версии не выдуман и не опубликован.
4. Выполните `npm run seo -- https://<рабочий-домен>` и сохраните сгенерированные SEO-файлы в Git.
5. Проверьте сайт на реальном iPhone и Android, звонок по `tel:`, полноэкранную карту и HTTPS.
6. После публикации проверьте код 404 для отсутствующей страницы, `_headers`, robots и sitemap на техническом домене. Зарегистрируйте sitemap в Google Search Console и Яндекс Вебмастере.

## Обновления и кэш

Меняйте информацию об объекте в `public/assets/js/objects.js`; затем commit/push в подключённый репозиторий. JS/CSS требуют перепроверки кэша (`no-cache`), фото кэшируются сутки. При замене фотографии используйте новое имя файла, чтобы посетители сразу получили новую версию. Откат — возврат коммита или предыдущей версии в панели Cloudflare.
