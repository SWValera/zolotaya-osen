# «Золотая осень»

Опубликованный сайт: **https://zolotaya-osen.arshavin-ivan-mail-ru.workers.dev/**. Работает на Cloudflare Workers Static Assets; собственный домен будет подключён отдельно.

Рабочий статический сайт базы отдыха: HTML5, CSS3, Vanilla JavaScript и SVG. Без сборки, runtime-зависимостей, серверного кода, базы данных и платных API. Текущий этап — знакомство с территорией и объектами; онлайн-бронирования и проверки свободных дат нет.

## Быстрый запуск

Из корня проекта:

```sh
python3 -m http.server 8080 --directory public
```

Откройте http://localhost:8080. Можно использовать `npm start` (нужны Node.js и Python). Установка npm-пакетов для запуска сайта не требуется. Двойной щелчок по HTML (`file://`) не подходит: браузер блокирует ES-модули.

Данные объектов находятся именно в `public/assets/js/objects.js`, как предусмотрено ТЗ. Отдельная копия данных в JSON не нужна: каталог JavaScript содержит и поведение, и ясно выделенный файл данных. `public/pages/` зарезервирован для будущих страниц; главная находится в корне публикации ради адреса `/`.

## Изменение цены

Откройте `public/assets/js/objects.js`, найдите объект по ID и дополните последний аргумент `object(...)`:

```js
object('river-1', 'Домик у реки № 1', 'house',
  'Подтверждённое описание',
  '342,185 404,184 428,246 398,261 335,247',
  {
    price: { amount: 45000, currency: 'KZT' }, // пример, не реальная цена
    priceUnit: 'сутки'
  }
),
```

Пример показывает формат, а не опубликованную стоимость. Укажите подтверждённую сумму и валюту (`KZT`, `RUB` или другой ISO 4217). `price: null` выводит «Стоимость уточняется». Цена сразу меняется и в списке, и в карточке после перезагрузки страницы. Базовые значения заданы в `defaults`; не меняйте их ради цены одного объекта.

## Фотографии и галерея

1. Поместите подтверждённые фотографии в `public/assets/images/objects/<id>/`.
2. Рекомендуется WebP, длинная сторона 1200–1600 px, примерно 150–300 КБ на фото.
3. Добавьте в последний аргумент объекта:

```js
photos: [
  {
    src: "./assets/images/objects/river-1/exterior.webp",
    alt: "Домик № 1 — вид со стороны дорожки",
  },
  {
    src: "./assets/images/objects/river-1/bedroom.webp",
    alt: "Домик № 1 — спальня",
  },
];
```

Первый снимок — основной. Остальные появляются по кнопкам галереи, загружается только выбранный снимок. Все файлы должны находиться внутри проекта. При `photos: []` показывается аккуратная заглушка, при ошибке файла — сообщение с возможностью перейти к следующему фото. Демонстрационное фото первого экрана не используется как фото конкретного домика.

## Новый домик

1. Добавьте одну запись в массив `objects` через `object(...)`.
2. Задайте уникальный ID, название, тип (`house`, `bath`, `gazebo`, `place`), описание и геометрию.
3. Дополнительные поля: `price`, `priceUnit`, `capacity`, `beds`, `amenities`, `photos`, `status`, `opening`.

```js
object('new-house', 'Новый домик', 'house',
  'Подтверждённое описание нового домика.',
  null, // до появления точного контура на согласованном генплане
  {
    capacity: null,
    beds: null,
    amenities: [],
    photos: [],
    price: null,
    status: 'unconfirmed'
  }
),
```

Запись автоматически появится в списке с рабочей карточкой. `mapAreaId` формируется как `area-<id>`, его можно переопределить в последнем аргументе. Для клика на карте замените `null` координатами контура: `'x1,y1 x2,y2 x3,y3 ...'`. Это пиксели **исходного изображения 1084 × 1280**, а не проценты и не координаты экрана. Изображение и полигоны масштабируются и перемещаются вместе в SVG, поэтому привязка сохраняется. Новый объект вне существующего генплана нельзя честно разместить на карте до обновления исходного генплана. Не подставляйте случайный контур.

Для обновлённого генплана сохраните исходную геометрию либо обновите `mapConfig` и все контуры под новое изображение. Для существующего генплана ни расположение, ни пропорции зданий не менялись.

## Статусы и неизвестные данные

- `unconfirmed` — «Готовность уточняется» (сейчас у всех объектов).
- `available` — «Доступен», задаётся только после подтверждения.
- `building` — «Строится».
- `planned` — «Планируется».
- `unavailable` — «Временно недоступен».

Поле `opening` — подтверждённый текст о будущем открытии для `building` и `planned`; без него дата не выдумывается. `capacity`, `beds` и `price` равны `null`, пока информации нет. Пустые удобства не заменяются предположениями. `available` означает готовность объекта, а не свободные даты.

## Контакты

В начале `objects.js` находится `contact`. Указан предоставленный номер `+77763055000` (+7 776 305-50-00). Из раздела контактов и любой карточки открывается окно с кнопкой звонка `tel:`. Можно добавить подтверждённый email или Telegram URL вида `https://t.me/name`. Если контакты очищены, интерфейс сообщает об их отсутствии.

## Карта и доступность

- Нажатие на объект или строку списка: выделение, приближение, карточка.
- Закрытие карточки / Escape: возврат к общему виду.
- `+`, `−`, `↺`: масштаб и сброс.
- На телефоне встроенная карта не блокирует прокрутку страницы.
- «На весь экран»: масштаб двумя пальцами, перемещение одним; на компьютере также колесо мыши и стрелки клавиатуры.
- Карточки — нативные диалоги с удержанием фокуса, на телефоне открываются снизу.
- Поддержаны Tab/Enter/Space, возврат фокуса, reduced motion и safe-area.

## SEO и публикация

Title, description, H1 и основные коммерческие тексты находятся в `index.html`. Канонический адрес и sitemap намеренно не содержат выдуманный домен. После выбора рабочего домена выполните:

```sh
npm run seo -- https://YOUR-REAL-DOMAIN.kz
```

Замените пример настоящим доменом. Скрипт создаст `public/robots.txt`, `public/sitemap.xml`, добавит canonical и `og:url`. В sitemap включается только главная, без дублей страниц домиков. При появлении самостоятельных страниц дополняйте sitemap. Для предпросмотра не индексируйте демонстрационную копию: можно использовать закрытый доступ хостинга или временный `X-Robots-Tag: noindex`.

Подробная настройка бесплатного статического размещения: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Проверки

```sh
npm run check
```

Браузерные проверки требуют отдельно установленного Playwright и Chromium; это инструменты разработки, сайт их не загружает. Сервер должен работать на порту 8080. Из корня проекта:

```sh
node tests/browser.mjs
node tests/interactions.mjs
```

При системном браузере задайте `BROWSER_PATH=/path/to/chromium`; при нестандартном расположении Playwright — `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs`. Результаты и оговорки о реальных устройствах: [docs/QA.md](docs/QA.md).
